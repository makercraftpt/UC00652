Revisão — O Semáforo como FSM

3 estados · 2 bits · ciclo automático controlado por TIMER
3 / 9

Diagrama de estados

O problema a resolver

  • O semáforo muda de estado quando TIMER=1
  • Quando TIMER=0, fica no estado atual (self-loop)
  • Precisamos de calcular D₁ e D₀ — as entradas dos FF-D
  • Na Aula 6 usámos equações derivadas à mão
  • Hoje usamos um MUX 2:1 — mais direto e mais visual

A questão chave

"Qual o valor de D no próximo ciclo de clock?"

Se TIMER=0: D = Q (fica igual — self-loop)
Se TIMER=1: D = Q' (vai para o próximo estado)
Esta escolha entre dois valores consoante um sinal de controlo é exatamente a função de um MUX 2:1.

A Fórmula MUX

D = (T̄·Atual) + (T·Próximo) — fica ou avança?
4 / 9

MUX 2:1 como seletor de estado

D = (T̄ · Atual) + (T · Próximo)

Calcular Q_next para o semáforo

Q_next é o estado para onde vamos se o TIMER disparar. Calculamos uma vez, a partir da tabela, e ligamos como entrada A₁ do MUX.
Estado atualQ₁Q₀→ PróximoD₁_nextD₀_next
VERDE00AMARELO 0101
AMARELO01VERMELHO 1010
VERMELHO10VERDE 0000

Leitura das colunas D_next

D₁_next = Q₀ // 0→0, 1→1, 0→0 — é exatamente Q₀!
D₀_next = NOR(Q₁,Q₀) // 1 só quando Q=00

Equações finais dos MUX

D₁ = T̄·Q₁ + T·Q₀
D₀ = T̄·Q₀ + T·NOR(Q₁,Q₀)
Sem Karnaugh, sem álgebra de Boole longa. O MUX encapsula a escolha fica/avança — as equações emergem direto da tabela.

Extensão — Botão de Peões

Chama o vermelho mais cedo · sem novos estados · só lógica extra
6 / 9

Comportamento desejado

  • Em VERDE: se o peão prime o BTN, avança para AMARELO imediatamente (sem esperar o TIMER)
  • Em AMARELO e VERMELHO: o BTN é ignorado — só o TIMER conta
  • O número de estados não muda — continuamos com 3 estados e 2 FF-D
  • É uma condição de avanço composta — dois sinais que podem causar transição

A condição AVANÇA

VERDE = NOR(Q₁, Q₀) // já tínhamos!
BTN_ATIVO = BTN · VERDE // filtra BTN só em VERDE
AVANÇA = TIMER + BTN_ATIVO
substituir TIMER por AVANÇA nos dois MUX
Bónus elegante: NOR(Q₁,Q₀) já existia no circuito como entrada A₁ do MUX D₀. Reutilizamos esse fio — um AND + um OR e o BTN fica integrado.

Saídas dos peões (opcional, sem novos estados)

LED_PEÃO_VERMELHO = Q₁' + Q₀ // estados 00 e 01
LED_PEÃO_VERDE = Q₁ · Q₀' // estado 10 (VERMELHO carros)

Diagrama de ligações com BTN

Em AMARELO e VERMELHO, o BTN_ATIVO é sempre 0 (VERDE=0 filtra o BTN). Portanto AVANÇA = TIMER nesses estados — o comportamento base não muda.

As 3 temporizações com 555 + 74HC4020

  • O NE555 em astável gera um clock lento (~1 Hz com RC adequados)
  • O 74HC4020 conta esses pulsos — cada saída Qₙ ativa ao 2ⁿ pulso
  • VERDE → tap Q₃ (8 pulsos = ~8 s)
  • AMARELO → tap Q₁ (2 pulsos = ~2 s)
  • VERMELHO → tap Q₂ (4 pulsos = ~4 s)
  • O estado atual (Q₁Q₀ dos FF-D) seleciona qual tap está ativo — via portas AND
  • Quando TIMER dispara → reseta o 74HC4020 via CLR → inicia nova contagem
Este "selector de timing" é equivalente a ter 3 temporizadores TON independentes num PLC — um por estado. O chip 74HC4020 substitui os 3 timers de software com taps de hardware.

A fórmula MUX é a lógica dos PLCs

O que estão a programar no LogiSim é exatamente o que um PLC Siemens S7 faz internamente quando usa um GRAFCET (Sequential Function Chart):

SET estado_amarelo
RESET estado_verde
